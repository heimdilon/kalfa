# Kalfa 1.1a-2 — Yerel MCP: Uygulama planı

**Tarih:** 2026-10-15. **Durum:** r1; Görev 1–11 tamamlandı; sıradaki ürün işi Görev 12. Son birleştirme kararı kullanıcıda.
**Taban:** `main`, `cf4e5f3962a7786460c398603ddd2c2536d9da43` (PR #19 squash).
**Tasarım:** [yerel MCP r9](../specs/2026-10-14-kalfa-11a-mcp-yerel-design.md).
**Görev:** KALFA-20 / KALFA-24, Codex. Kullanıcının son alt ajan tercihi GPT-6 Luna / max.

Amaç: Ayarlar'dan eklenen yerel stdio sunucusu, ayrı başlatma izni ve
her çağrının izin/mühür/kilit denetimiyle çalışır. Denetlenmiş araçlar
model turunun başında tek görüntüye alınır. İptalde süreç durduğu ve son
çalışma alanı denetimi tamamlandığı doğrulanmadan kilit çözülmez.

Bu plan görevleri, dosyaları, veri sahipliğini ve karşı örnekleri belirtir;
gelecekteki ürünün tamamının yazılmış/derlenmiş olduğunu iddia etmez.
Plandaki gerçek SDK bağlantısı `prototip/mcp-tasima/` kaynaklarıdır;
iki platformda ön doğrulanmıştır. Diğer görevler davranış sözleşmesidir,
derlenmemiş Rust uygulama blokları içermez. Ön doğrulamanın kapsamı ve
sonraki kabul kapıları [G2 raporundadır](../bulgular/2026-10-15-kalfa-11a-2-on-dogrulama.md).

## Global Constraints

- 1.1a-1'in `EtkilesimliSurec`, `CalistirmaKipi`, özel kök, yetenek SID'i
  ve doğrulanan `kapat()` sözleşmeleri aynen kullanılır. Yalıtım sessizce
  tam erişime düşmez. Tam erişim ayrıca seçilir, yerel onay ister.
- Yeni paket yalnız tasarımdaki `rmcp =3.5.1` ve zorunlu geçişli
  bağımlılıklarıdır. Üretimde default özellikler kapalı, `client` açık;
  test sunucusunda ayrıca `server` açık. Yeni HTTP/OAuth/child-process
  taşıması yok. Mevcut workspace paketleri yeniden kullanılır.
- `server`, SDK içinde `transport-async-rw` özelliğini geçişli açar.
  Bu, Kalfa'nın istemcide bu taşıma yolunu kullandığı anlamına gelmez.
  Ürün ve test istemcileri özel `Transport<RoleClient>` kullanır.
- Bu plan yeni `unsafe` gerektirmez. Gerekirse uygulayıcı durur, ayrı
  gerekçeyi PR'a yazar; kendiliğinden izinli dosya listesi büyütmez.
- Üretimde `unwrap`/`expect` yok; Türkçe adlar, hata metinleri ve testler.
- Çalışma alanından `.mcp.json` okunmaz. Model sunucu ekleyemez,
  düzenleyemez, başlatma izni veremez veya tam erişim seçemez.
- İstemci `roots`, `sampling`, `elicitation` yetenekleri ilan etmez.
  `ping` yanıtlanır; öbür sunucu istekleri `-32601` alır.
- Sır; ayarlar, cache, UI durum/olayları, JSONL, gönderim günlüğü ve hata
  metinlerine ham yazılmaz. Tanımda sır bulunursa maskelemek yerine araç
  kapatılır. Sır denetimi D hesabından ve her cache isabetinden de öncedir.
- SDK yanıt cache'i ilk `tools/list` öncesinde
  `ClientCacheConfig::disabled()` ile kapatılır. Kalfa'nın denetlenmiş
  tanım cache'i bunun yerine geçer. SDK'nin ham yük içeren tracing
  olayları hiçbir log katmanına geçirilmez; yalnız Kalfa'nın maskeli,
  yapılandırılmış olayları kaydedilir. Debug etkinleştirmek bunu açmaz.
- Ağ yok, EVREN'e çıktı yok anlamına gelmez. §4.3'te kabul edilmiş kalan
  risk ve tam erişimin §4.1'de kabul edilmiş ayrı sınırı korunur.
- Canlı EVREN deneyi ayrı onaylı/ignore'dır. Şart kabul ucu çağrılmaz.
  Yeni kurulum/sistem ayarı ve PR merge'i ayrıca kullanıcı yetkisi ister.
- Her görevde ilgili test önce eski/eksik davranışta düşürülür, sonra
  uygulama yapılır. Güvenlik testleri sahte bileşenlerle hata yolunu,
  iki platformun gerçek yalıtım takımıyla OS sınırını ayrı ölçer.

## Argüman yolları — kullanıcı kararı

Tasarım §5.1.1, dosyaya çözülen argümanların içeriğinin özetlenmesini
ister. §9 ise "Argümanlar programa verilen metinlerdir; Kalfa onları yol
olarak açmaz" der. İki cümle birlikte uygulanamaz. Kullanıcı 15 Ekim 2026 tarihinde bu
oturumdaki karar sorusuna doğrudan “Yerel onaydan sonra dosya özeti alınsın” dedi.

**Onaylanan açıklama:** Argüman, programa verilen metindir; arayüze genel
dosya okuma yetkisi vermez. Arka uç, yalnız tam komut satırının gösterildiği
yerel kayıt onayından sonra, açıkça dosyaya çözülen argüman/ortam yollarını
§5.1.1'deki kod güveni hesabı için açıp özetleyebilir. İçerik arayüze veya
modele verilmez. Yerel onaydan önce dosya içeriği okunmaz. İşletim sistemi
tarafında çözülen yürütülebilir yol ve çalışma alanı kimlikleri arka uçta
kalır; komut seçici mevcut yol/kimlik sınırına uyar.

Bu kayıt §4.1 ve §4.3 risk kabullerinden ayrıdır. Kaynak, bu oturumdaki
insanın doğrudan yanıtıdır; başka bir ajanın özeti değildir. Tasarım r9
§9 ve §13.8 bu dar açıklamayı taşır.

## Bileşenler ve bağımlılıklar

| Katman | Somut değişiklik |
|---|---|
| `kalfa-mcp` (yeni) | Tanım/tarif, sır maskeleme, sınırlı taşıma, SDK istemcisi, liste ve sonuç dönüşümü, `Arac` sarmalayıcısı |
| `kalfa-core` | MCP tarifi/izin/kısayol, tur görüntüsü, tanım denetiminin bütçe/olay akışı, kapanışta kilit devri |
| `kalfa-tools` | Kabuğun koruma hazırlığı ve son denetimini paylaşılabilir uçlara ayırma; yazma kuşağı bağlantısı |
| `kalfa-sandbox` | Tarama tamlığı ve işbirlikçi 30 sn durdurma; süreç altyapısı yeniden yazılmaz |
| `kalfa-uygulama` | Ayarlar/kasa, çalışma alanı başına süreç sahibi, yerel onay, zamanlayıcı ve oturum yaşamı |
| `kalfa`, `ui`, `e2e` | Kimlik tabanlı IPC, MCP Ayarlar/kartlar, gerçek uygulama kabul akışı |

Bağımlılık yönü: core → evren; sandbox bağımsız; tools → core/sandbox;
mcp → core/sandbox; uygulama → core/tools/sandbox/mcp. Core, mcp'ye
bağımlı olmaz. MCP araç kaynağının arayüzü core'da tanımlanır;
uygulama yöneticisi ve MCP sarmalayıcıları onu doldurur. Kabuğun koruma
işini yeniden yazmak yerine tools'un ortak ucu uygulama tarafından kullanılır.

## G2 — Ön doğrulanmış SDK bağlantısı

- [x] `prototip/mcp-tasima/` bağımsız Cargo workspace'i; ürün workspace'ine girmez.
- [x] Gelen satır ≤ 4 MiB; UTF-8 bölünmeleri, çok satır ve yarım EOF.
- [x] 64 gelen ileti; 65'inci ileti taşmada hata kanalı oluşturur.
- [x] 1.000 liste bildirimi tek yenileme bayrağı olur, SDK işleyicilerine akmaz.
- [x] Auto başlangıcı eski ve 2026 dönemli sentetik sunucuyla çalışır.
- [x] Eski dönemde `notifications/initialized`, boş yetenekler; iki dönemde liste, ping ve desteklenmeyen istek reddi.
- [x] Yeni dönemde stdio `subscriptions/listen` onayı çalışır; liste değişikliği bayrağı güncellenir.
- [x] Pozitif `ttlMs` ile SDK cache'i kapalıyken iki listeleme iki RPC üretir.

Kuyruk sınırı **ileti adedidir**; toplam belleğe 64 MiB gibi bir üst sınır
iddia edilmez. Ayrıştırılmış JSON ve kopyalar ek bellek tutabilir. G2
süreç kapatmayı, stdout hızına karşı bütün uygulamanın belleğini,
stderr maskelemesini veya arayüzü doğrulamaz. Üründeki kapanış/hata,
aktif sel ve sır testleri aşağıdaki görevlerde zorunludur.

## Uygulama sırası

Görev 1–3 temel sözleşmeler; 4–6 bunlara; 7–9 süreç sahibine; 10–12 bütün
arka uca bağlıdır. Ayrı ajanlar aynı worktree'de eşzamanlı yazmaz. Her
görev ayrı commit ve bağımsız incelemeyle kapanır. Uygulayıcı, belirtilen
test ölçülmeden sonraki görevi tamamlanmış işaretlemez.

## Doğrulama komutları

G2, iki platformda (üretim workspace'ini değiştirmez):

```sh
cargo test --manifest-path prototip/mcp-tasima/Cargo.toml --locked -- --test-threads=1
cargo clippy --manifest-path prototip/mcp-tasima/Cargo.toml --all-targets --locked -- -D warnings
cargo fmt --manifest-path prototip/mcp-tasima/Cargo.toml -- --check
```

Ürün uygulamasında, her görev için ilgili filtreli testten sonra AGENTS:

```sh
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all -- --check
cargo test -p kalfa-uygulama -p kalfa --features e2e --locked
cargo clippy -p kalfa -p kalfa-uygulama --features e2e --all-targets --locked -- -D warnings
cargo clippy -p kalfa-sandbox -p kalfa-tools --features "kalfa-sandbox/yalitim-testleri kalfa-tools/yalitim-testleri" --all-targets --locked -- -D warnings
cargo build -p kalfa-sandbox --bin kalfa-kopru --locked
cargo test -p kalfa-sandbox --features yalitim-testleri --test yalitim --locked -- --test-threads=1
cargo test -p kalfa-tools --features yalitim-testleri --test uyumluluk --locked -- --test-threads=1
```

Yeni MCP gerçek yalıtım test hedefinin adı `yalitim` olur:

```sh
cargo test -p kalfa-mcp --locked
cargo test -p kalfa-mcp --features yalitim-testleri --test yalitim --locked -- --test-threads=1
```

`yalitim-testleri` aynı adlı sandbox özelliğini iletir; test sunucusu ürün
kurucusuna girmez. Köprü testten önce güncel derlenir. Linux komutları
Ubuntu-24.04 `kalfatest`, root olmayan hesap; Windows da yönetici olmayan
hesap. CI'ya özgü kullanıcı/ACL betiği geliştirici makinesinde çalıştırılmaz.

Arayüzde `npm ci`, `npm run check`, `npm test`, `npm run build`; e2e'de
mevcut `npm ci`, `npm test` (Linux Xvfb) komutları uygulanır. İndirilecek
bir şey yoksa mevcut kurulum yeniden kullanılabilir; eksik pakette yeni
indirme kapsamı önce doğrulanır. Check 0 hata/uyarı. WebDriver gereksinimi
mevcut AGENTS ile aynıdır. G2 CI adımları ürün testleri taşınırken aynı
PR'da sadeleştirilebilir; test kaldırmanın yerine ürün karşılığı konur.
